## Messages

**Messages** sends a message to a colleague or a department, optionally linked
to a record.

Useful for things that need a person but not a telephone call: asking a
colleague to review an unusual result, flagging a recurring specimen problem,
handing over at shift change.

**It is not for urgent clinical communication.** A critical value needs a
telephone call with
[read-back](/help/clinical-decision-support/critical-values/). A message sits
unread until somebody signs in.

## System alerts

**Settings → System alerts** puts a banner on every screen for everyone.

| Type | Use for |
| --- | --- |
| Information | A planned change, a new procedure |
| Warning | A degraded service, an analyser down |
| Error / Critical | Something requiring immediate awareness |

Set an expiry. A banner that has been there for three months is invisible — and
worse, it teaches people to ignore banners, so the next genuinely urgent one is
also ignored.

Alerts are dismissed per person, so each user sees one until they have read it.

## Feedback

**Feedback** raises a bug, a feature request or a general comment. Managers see
everything; everyone else sees their own.

Use it for the system itself. A laboratory **incident** — something that went
wrong with a specimen, a result or a patient — belongs in
[nonconformances](/help/quality/corrective-actions/), where root cause and
corrective action are recorded.

The distinction matters: feedback improves the software; a nonconformance
protects patients.
